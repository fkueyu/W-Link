# W-Link 深化改造说明

## 1. 本轮目标

本轮围绕“优雅、快速、适合单手操作的 WLED 移动控制器”深化现有体验，不扩张无必要的功能面。核心原则是：设备当前发出的光成为界面的一部分；常用控制一步可达；网络反馈与真实状态一致；动效不牺牲性能与无障碍体验。

## 2. 已优化的体验

### 2.1 控制页光场

- 控制页背景由设备当前主色动态驱动，开灯时呈现对应颜色的柔和环境光，关灯后自动收暗。
- 采用独立重绘边界隔离光场动画，避免控制组件被持续重绘。
- 宽屏双栏模式移除多余的顶部导航占位，提升 iPad 和桌面端有效空间利用率。
- 宽屏应用壳现在是全局极光背景的唯一所有者，嵌入的设备列表改为透明承载内容，避免两套持续动画叠加绘制；设备详情的动态光场仍作为局部状态反馈保留。

### 2.2 首页设备总览

- 新增首页状态概览条，同时展示在线设备数、设备总数和局域网状态。
- 下拉刷新改为真正等待每台设备完成强制刷新，不再使用固定延迟模拟刷新完成。
- 保留设备卡片的实时色彩、亮度、开关和在线状态反馈，使首页可以直接完成高频控制。

### 2.3 调色体验

- 快捷色支持长按覆盖，并通过 `SharedPreferences` 持久化；关闭应用后仍会保留。
- 存储数据异常或版本不兼容时自动回退到经过整理的默认色板，不影响调色面板打开。
- 快捷色区域补充操作提示和中英文文案，避免隐藏交互难以发现。

### 2.4 交互反馈与可访问性

- 开关、亮度拖动和快捷色覆盖保留分级触觉反馈。
- 控制页开关和亮度滑块补充语义标签，读屏可识别当前开关状态与亮度百分比。
- API 尚未就绪时禁用相关控制，避免空引用和无效操作。
- 全局极光与设备光场均尊重系统“减少动态效果”设置，开启后停止循环动画。
- Toast、卡片、滑块等现有玻璃态组件统一保持低干扰反馈层级。
- 自定义 `BouncyButton` 从仅支持触摸升级为统一的可访问交互入口：支持 Tab 聚焦、Enter/Space 激活、品牌紫焦点环、按钮启用状态和读屏标签。
- 显式读屏标签会替代子节点的重复播报；未提供标签时继续保留子文本语义。禁用按钮不接受键盘焦点和激活。
- 首页纯图标搜索按钮补充本地化语义名称；原本没有实际行为的应用图标不再伪装成可点击按钮。
- 修复宽屏 340px 设备栏标题行溢出，标题与副标题会在剩余空间内弹性收缩并安全省略。

### 2.5 设备会话与通信可靠性

- 新增按设备 ID 唯一的 `deviceSessionProvider`。设备卡片、详情页、效果、调色板、预设、计划和分段页面复用同一套 HTTP、WebSocket 与轮询状态，不再为同一设备建立 detail/family 双会话。
- 会话只监听 IP、端口和 Base URL 等稳定连接身份；在线状态、设备名称和 `lastSeen` 回写不会销毁并重建 WebSocket。
- 删除双会话之间的 `_syncToPeer` 状态桥，避免状态更新顺序不一致以及读取对端 notifier 时意外创建第二个连接。
- 当前设备的 API provider 改为复用设备会话中的 HTTP client；卡片开关与亮度也不再临时创建 client。
- 轮询增加进行中保护，避免慢请求与下一轮轮询重叠；连续失败后会把设备标为离线。
- 命令加入递增序号。旧请求晚于新请求返回时，不会再覆盖用户最后一次操作。
- 乐观更新成功后采用 WLED 返回的权威状态；失败后恢复操作前快照，并返回显式 `DeviceCommandResult`，调用端可以安全区分成功和失败，未迁移的 fire-and-forget 调用也不会产生未处理异步异常。
- 删除分段直接采用 WLED 返回的权威状态，移除了页面层固定 500ms 延迟强刷，避免旧 GET 绕过命令顺序保护。
- HTTP GET/POST 统一检查 2xx；非成功响应、无法解析的状态、超时和连接异常都通过 `WledApiException` 明确表达，不再静默返回 null 或暴露多套异常类型。

### 2.6 主分段一致性

- `WledState` 新增 `mainSegment`，按 WLED 的真实 `mainseg` ID 查找主分段，固件返回失效 ID 时安全回退，空分段不会越界。
- 新增 `replaceSegmentById`，所有主分段乐观更新按真实 ID 替换并保持列表顺序。
- 控制页效果参数、调色板、颜色选择与设备卡片环境色改用同一主分段规则，API 请求同步携带真实 Segment ID。

### 2.7 高频颜色与错误反馈

- 新增通用 `LatestValueDispatcher<T>`：色盘拖动时界面逐次响应，但网络同一时间最多发送一个请求；等待期间的中间颜色会被覆盖，只发送最终值。
- 色盘关闭后不再接收新值，但会继续送达已经排队的最终颜色，避免慢网络下吞掉用户最后一次选择。
- 主控制页和分段色盘都使用相同调度逻辑，不再为每个拖动触点直接创建 HTTP POST。
- 色盘打开时固定捕获目标设备 session；宽屏切换设备后，排队颜色不会污染新设备状态。已经释放的 session 会安全拒绝延迟命令。
- 调度器会捕获异步发送异常、记录并可选上报，然后继续处理最终值，不产生无人监听的 Future 异常。
- 设备命令失败会发布带序号和设备 ID 的统一失败事件；最外层 `AdaptiveShell` 是唯一 Toast 监听出口，窄屏和宽屏都不会重复提示。
- 新增中英文控制失败文案；底层服务继续保留原始错误，用户界面只展示简洁、可行动的提示。

### 2.8 Nightlight 单一编辑器

- 将独立页面和设备设置面板中的两套 Nightlight 控制合并为唯一 `NightlightEditor`；开关、时长、目标亮度和四种模式不再重复维护。
- 设备设置面板只保留 `NightlightSummaryCard` 状态摘要和入口，避免高级设置里出现第二套 Switch、Slider 和模式选择器。
- 新增 `NightlightScreen` 作为唯一完整页面；旧 `ScheduleScreen` 收敛为 deprecated 兼容薄包装，已有外部引用不会立即失效。
- 用户界面标题从协议术语 Nightlight 和泛化“定时任务”改为“定时关闭与渐暗”/“Sleep Timer”，避免把倒计时误解成日程自动化；四种模式名称全部使用本地化资源，删除中英文硬编码。
- `WledApiService.setNightlight` 改为接收完整 `WledNightlight`，请求只发送 `on`、`dur`、`mode`、`tbri` 四个可写字段，不回传设备只读的 `rem`。
- `DeviceStateNotifier.updateNightlight` 复用统一乐观更新链：界面即时变化、成功采用设备权威响应、失败回滚并显示全局错误，删除页面层直接 API 后立即 `refresh()` 的旁路。
- Nightlight 开关向读屏报告能力名称和开关状态；模式卡暴露选中状态，并继承统一的键盘激活与焦点反馈。
- 所有设备写命令现在按 session 串行发送，避免较旧 HTTP 请求在设备端后执行而覆盖较新意图；界面仍立即进行乐观更新。
- 轮询 GET 在发出时记录命令序号，响应到达后再次校验；期间只要出现用户命令，旧状态就会被丢弃。
- 连续命令以最后一次设备已确认状态为回滚基线；即使多个排队命令都失败，也不会停留在临时乐观快照。

### 2.9 首页设备状态胶囊

- 删除首页顶部独立占行的设备概览卡，将在线数、设备总数和网络状态收进“我的设备”标题右侧，首屏层级从“概览卡—品牌—标题—列表”收敛为“品牌—标题与状态—列表”。
- 胶囊只突出一个视觉记忆点：在线状态使用带轻微光晕的绿色脉冲点；设备总数和网络图标降为次要灰阶，断网时才切换为警示色。
- 状态胶囊支持点击刷新全部设备，与下拉刷新复用同一条会话刷新路径；每台设备会话会向所有调用者返回同一个在途刷新 Future，因此两个入口的进度都等待真实网络请求结束，不会出现一边提前收起。
- 保留断网时下方可行动的完整提示，胶囊不重复展示长文案；读屏仍能一次获取在线数、总数和局域网状态。
- 增加中英文紧凑宽度、共享在途刷新、进度反馈和标题同行测试，覆盖 340px 双栏左侧及 320px 组件宽度。

## 5. 验证范围

- 快捷色覆盖后重新创建状态对象仍能恢复。
- 快捷色存储损坏时回退默认色板。
- 设备开启时显示光场，关闭时移除彩色光场且保留控制内容。
- 首页概览正确呈现设备、在线和局域网状态。
- 开启减少动态效果后不再残留循环帧回调。
- 详情投影与设备卡片读取同一个 session notifier。
- 命令失败恢复最后已确认状态；写请求串行执行，命令期间返回的旧 GET 不覆盖较新的设备状态。
- HTTP 503 与非法 JSON 均产生包含状态码、路径的明确异常。
- 非 0、非首位的主分段仍能正确显示和控制。
- 首个颜色请求阻塞时连续选择三个颜色，网络只收到第一个和最后一个。
- 关闭颜色面板后已排队的最终颜色仍会送达，新提交则被忽略。
- 一次设备命令失败只产生一个带设备身份的事件，并由应用壳显示一次 Toast。
- Tab 可聚焦弹性按钮，Enter 与 Space 各触发一次主操作；禁用状态无点击语义且不获得焦点。
- 宽屏双栏只有一个全局 `AnimatedBackground`，且 340px 左栏不再发生横向溢出。
- Nightlight 请求不包含只读剩余时间；会话成功采用权威状态，失败恢复原值并只发布一次失败事件。
- Nightlight 关闭时隐藏参数，开启后显示两个滑块和四个模式；模式切换保留其余字段并向读屏报告选中状态。
- Nightlight 开关向读屏报告本地化名称与开关状态；两个重叠命令均失败时恢复命令批次开始前的已确认基线。
- 390px 小屏页面使用唯一编辑器且无布局溢出；设置摘要不包含第二套控制。
- 首页状态胶囊与“我的设备”保持同行；紧凑宽度无溢出，连续点击只启动一次刷新并提供原位进度反馈。
- 全量静态分析与 Flutter 测试作为最终交付门槛。

最终验证：82 个 Dart 文件格式一致，静态分析 0 问题，79 项 Flutter 测试全部通过，差异完整性检查通过；独立复审未发现未解决的 Critical、Important 或 Minor 问题，结论为 Ready。

## 6. 设计取舍

现有 UDP Realtime 服务暂不直接绑定调色盘。WLED 的实时 UDP 模式会短暂接管常规效果状态，在未设计完整的进入、续期和退出策略前直接启用，可能造成效果被抢占或状态不同步。本轮继续使用 HTTP 写入、WebSocket 接收和轮询兜底，优先保证控制结果可预测。

完整视觉令牌与对比度收敛、其余纯图标按钮的逐页语义命名、真正的日程自动化能力，以及真实 WLED 抓包验证仍属于后续阶段，本轮不把它们描述为已完成。
