# 贡献指南 (Contributing)

首先，非常感谢您对 W-Link 项目感兴趣并希望做出贡献！W-Link 秉承开源互助的精神，无论是修复 Bug、添加新功能、改进文档还是提供设计建议，我们都十分欢迎。

在您开始提交代码之前，请花几分钟阅读以下指南。

## 核心开发理念 (Core Philosophy)

在深入代码之前，请了解我们的开发原则，这是合并 PR 的重要标准：

1. **拒绝废话 (No Fluff)**：代码应该是不言自明的。避免编写无意义的注释，命名要精准直白。直接解决问题，不要过度设计。
2. **现代化 (Modern Standards)**：必须使用 Dart 3.0+ 特性（如空安全、Records 记录类型、Patterns 模式匹配）。禁止在任何地方使用 `dynamic` 进行无类型约束的编程。
3. **防御性编程 (Defensive)**：涉及硬件和局域网通信，永远假设网络是不稳定且脆弱的，WLED 设备随时可能断电。请务必处理所有的 `SocketException` 和 `TimeoutException`。
4. **用户体验优先 (UX First)**：如果你的功能会阻塞主线程，或者引发 UI 掉帧，它将不会被合并。UI 响应必须快于网络请求（利用乐观更新）。

## 准备开发环境

1. **安装 Flutter SDK**: 请确保您的环境配置了最低 `3.10.0` 版本的 Flutter SDK。
2. **克隆仓库**:
   ```bash
   git clone https://github.com/fkueyu/W-Link.git
   cd W-Link
   ```
3. **安装依赖与生成代码**:
   ```bash
   flutter pub get
   dart run build_runner build -d
   ```
   *注意：本项目使用 Riverpod 和 json_serializable，任何涉及模型或状态类的修改，都需要运行上述生成命令。*

## 提交流程

1. **提交 Issue**: 如果您要开发的是一个大功能或架构重构，请务必先在 GitHub 提交 Issue 讨论您的想法，以确保您的方向与项目整体规划一致，避免浪费您的宝贵时间。
2. **创建分支**: 从 `main` 分支拉出一个新的特性分支，命名清晰：
   - `feature/add-sync-mode`
   - `bugfix/fix-mdns-crash`
   - `docs/update-readme`
3. **编写代码**: 请严格遵守 `flutter_lints` 的语法规范。开发中尽量拆分细粒度的 Widget。
4. **测试您的代码**: 请在真实网络环境（至少一台真实的 WLED 设备或使用电脑模拟的 WLED 实例）下测试您的修改。确保多次快速开关、断电重连等极端情况不会导致 App 崩溃。
5. **提交 Commit**: 请使用清晰的 Commit 描述您的改动，尽量遵循 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/v1.0.0/) 规范（例如 `feat:`, `fix:`, `refactor:` 等）。
6. **发起 Pull Request**: 推送您的分支并提交 PR，我们会尽快审核。

## 提交反馈与建议

如果您不熟悉 Flutter 开发，您同样可以做出巨大贡献！
- 帮助我们翻译文档或应用内文案。
- 报告您在使用中遇到的 Bug。
- 提出您期望的新功能。
- 在各类论坛和社交媒体推荐我们的应用。

再次感谢您让 W-Link 变得更好！
