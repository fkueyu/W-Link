[P0 批次](../../../lib/screens/device_control_screen.dart) 已用判据把六处布局硬伤收口，但**没有任何一张真机截图**：
`84pt` 的瓦片高度、色盘弹层的外壳、键盘弹出后的弹窗位置，都是只在测试字体下验证过的推断。
本批补上真机截图，并据此修掉了两个用例测不出来的缺陷。

## 2. 缺陷 1：瓦片固定 84pt 在中文两行标题下溢出

**现象**（`截图/02-控制页-修复前-瓦片溢出4.6pt.png`）：402pt 宽的 iPhone，「定时关闭与渐暗」占两行，
瓦片底部出现红黑相间的 `BOTTOM OVERFLOWED BY 4.6 PIX`。

**为什么用例没拦住**：`flutter test` 用的是等宽方块测试字体，中文行高比 PingFang 小；
同样的 393×600 姿态档在用例里 `takeException()` 为 null。**这不是判据写错，是判据的字体口径与真机不同**。

**修法**（`lib/screens/device_control_screen.dart`）：

- `_kActionTileHeight = 84` → `_kActionTileMinHeight = 92`，并新增 `_actionTileExtent(context)`：
  按 `MediaQuery.textScalerOf(context)` 缩放，上限 168。
- 瓦片标题 `maxLines: 2` + `TextOverflow.ellipsis`，第三行必须截断而不是溢出。

**判据**（`test/screens/duo_postures_test.dart`）：原来那条「固定高度、`mainAxisExtent > 0`」是恒真的，
已换成三条：余量 ≥ 92、字号 1.6 倍时高度随之增长、标题 `maxLines == 2` 且省略。

## 3. 缺陷 2：色盘弹层「有玻璃填充、没有玻璃模糊」

**现象**（`截图/04-色盘-修复前-透字.png`）：弹层区域是一层 65% 白，**没有背景模糊**，
底下页面的「颜色」「定时关闭与渐暗」「速度」原样透上来，与「快捷色」叠字。

**根因**：`FluxTheme.glassDecoration` 只产出 `BoxDecoration`，模糊必须由 `BackdropFilter` 提供。
`GlassCard` 一直是「`ClipRRect` + `BackdropFilter(blur 10)` + 装饰」，设备设置弹层是「blur 30 + 0.85 填充」，
**只有色盘弹层直接用了装饰、漏了模糊**。

**修法**：新增 `lib/widgets/glass_sheet.dart`（`GlassSheet`：顶圆角 + blur 30 + 0.85 填充），
色盘弹层改用它。后续新弹层应复用，不要再手写一份。

## 4. 采集方式（可复现）

Xcode 27 这套机器**没有 GUI 版 Simulator**（`simctl` 可用、`Simulator.app` 不存在），
`screencapture` 也没有屏幕录制权限，所以「鼠标点、系统截图」两条路都走不通。

替代方案是 `tool/shots/main.dart` 这个临时入口：

- 它跑**真正的 `FluxApp`**，只在启动时把一台假设备（`127.0.0.1:8099`）写进 `SharedPreferences`；
- 指令从 App 沙盒 `tmp/shots_cmd.txt` 读，用 `GestureBinding.instance.handlePointerEvent`
  注入指针事件——**与真人点击走同一条命中测试与手势管线**，所以截出来的是真实交互结果；
- 主机侧 `xcrun simctl io <udid> screenshot` 取图；**每个场景前必须清空命令文件**，
  否则 App 重启后会重放旧命令（本批踩过：几张截图拍成了重放末尾的状态）。

后台的 WLED 用 `python3` 写的假设备（`/json`、`/json/info`、`/json/eff`、`/json/pal`、`/presets.json`）。
注意 iOS 沙盒里读不到 `HOME`，状态文件会落在 `<container>/tmp`，不是 `Documents`。

## 5. 本批**没有**验证到的（如实登记）

1. **短而宽的姿态（480×600、Duo 外屏 600 高）没有像素证据**。无头模拟器不能旋转、也不能自定义窗口尺寸；
   这类姿态目前只有 `test/screens/duo_postures_test.dart` 的断言（无溢出、色盘按高度预算收缩）。
2. **横屏 / 内屏 951×669 没有像素证据**，同上。因此 `_kContentMaxWidth = 680` 这个改动**在任何已截图的姿态里都不生效**：
   手机 402 宽、平板竖屏 834 宽（右栏约 492）都小于 680，只有横屏/宽窗才会被它夹住。**680 是否合适仍属推断。**
3. **R4（800pt 断点 + 342pt 左栏）没有改**。平板上左栏实测 342pt，在 Apple 侧栏 320–375 的建议区间内；
   但「Duo 内屏 951pt 上留 342pt 给列表是否浪费」需要横屏证据，本批拿不到，故不动。
4. **多场景 / 保留区域**（`UIApplicationSupportsMultipleScenes = false`）仍未动，属 P4。
5. 深色模式、大字号（Dynamic Type）未截图；瓦片高度的字号缩放只有用例覆盖。
