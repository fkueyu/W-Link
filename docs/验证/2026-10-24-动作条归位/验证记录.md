# 动作入口归位（列表头部 / 详情列右上）— 验证记录

- 日期：2026-10-24
- 版本：`2.4.5+12` → **`2.4.6+13`**
- 起因：「是不是应该把上面的搜索和菜单以及下面的添加设备放到工具栏去，这样他们就会显示到右边」

## 一、先纠正一个前提

这条建议里藏着两个可以分开判断的事：

1. **「放进工具栏，iOS 就会把它排到右边」——对 Flutter 不成立。**
   Duo 上「系统栏竖排到右侧」是 **UIKit / SwiftUI 导航条与工具栏**的行为。
   本 App 的条不是系统条，是自己画的：

   ```dart
   // lib/screens/device_control_screen.dart（改前）
   Positioned(top: 0, left: 0, right: 0, child: …)   // 位置写死在顶部
   ```

   换成哪个 iOS SDK 它都还在顶部。要「在右边」只能自己排。

2. **「这几个动作该收进一条栏、且不要底部浮动按钮」——成立，而且比原来更急。**
   查代码发现三处真缺陷（都不是审美问题）：

| # | 缺陷 | 证据（改前） |
|---|---|---|
| 1 | 头部的按钮是**放大镜 + 语义「搜索」**，`onTap` 却进发现页（等于加设备） | `device_list_screen.dart:178-179`：`semanticLabel: l10n.search` / `onTap: () => _navigateToDiscovery(context)` |
| 2 | 双栏模式把整个浮动按钮置空 → **宽屏一个加设备入口都没有** | `device_list_screen.dart:435`：`floatingActionButton: _isEmbedded ? null : …` |
| 3 | 嵌入模式把整条玻璃条跳过，连带 `tune` 的**唯一**入口一起跳过 → **宽屏打不开设备设置** | `device_control_screen.dart:125`：`if (!widget.embedded)`；全文件 `_showSettingsSheet` 只有一处调用点，就在这条分支里 |

第 3 条是这次最值钱的发现：它不在任何用例的覆盖里，也不会报错，只是「点了没反应的地方原来根本没有按钮」。

## 二、改了什么

| 位置 | 改动 |
|---|---|
| 列表头部 | 放大镜 → **`+`**，语义标签 `l10n.addDevice`；与「⋯」菜单并排成一条头部动作条 |
| 列表底部 | **删掉** `centerFloat` 浮动按钮（含 `_isEmbedded ? null` 那套分支）；加设备只留头部一个入口 |
| 控制页（嵌入） | 新增详情列右上动作条，补回 `tune`（设备设置），`key: device-settings-embedded` |
| 控制页（窄屏） | 不变：设置入口仍在玻璃条里，**不重复**出现第二条 |
| 空态文案 | 「点击下方按钮或右下角」→「点按右上角的 ＋ 或下方按钮」；英文同步。原文指向的位置在本次改动后已经没有任何按钮 |

## 三、算过但没做的：整条竖排 rail

Duo 内屏 951pt 宽，列表列 340pt。把「加设备 / 分组 / 设置」搬到窗口最右侧，动作离它们作用的列表约 **560pt**——比拇指到屏幕对角的距离还远。Apple 的竖排栏服务的是**整窗导航**；我们这里是「列表 + 详情」分栏，动作应当跟着自己的列走。

所以落成：**列表的动作在列表列顶部（贴该列右缘），详情的动作在详情列右上（贴窗口右缘）**。「在右边」在详情这一侧是字面成立的，并且有用例量它的坐标（见下）。

## 四、判据（5 条新增，`test/screens/action_placement_test.dart`）

1. 窄屏：头部有 `device-list-add`，且 `Scaffold.floatingActionButton == null`
2. 双栏左栏：**有设备时**入口仍可达（空列表会被 `EmptyState` 掩盖，所以特意塞了一台）
3. 语义标签等于 `添加设备`，且**不等于** `搜索`
4. 嵌入模式：设置入口存在、**贴右上**（右边距 ≤ 40pt、顶 ≤ 80pt）、点开能弹出 `DeviceSettingsSheet`
5. 窄屏：不出现嵌入动作条（避免两个入口）

## 六、没做到的

1. **双栏（Duo 内屏）没有像素证据。** 切姿态要 DeviceHub 的设备窗口按钮；这一轮它没有窗口（`AX windows = 0`），`open -a DeviceHub` / URL scheme / 重启 DeviceHub 都没能把设备窗口叫回来，重启还把 4 台模拟器都关了。所以「右上动作条」的外观只有用例的坐标断言（贴右 ≤40pt、贴顶 ≤80pt），**没有截图**。
2. **没能把设备塞进列表做「有设备」的截图**：`simctl spawn defaults write ink.ainx.flux flutter.flux_devices` 写的是模拟器的全局域，而 App 的 `NSUserDefaults` 落在容器里（容器内 `Library/Preferences/` 根本没生成），所以列表仍是空态。这条只影响取证，不影响判据（用例 2 是真的塞了一台设备跑的）。
3. **没有真机（非模拟器）证据**。
4. 分组管理、设置页里是否还有别的地方写着「右下角」，没有全仓扫。
