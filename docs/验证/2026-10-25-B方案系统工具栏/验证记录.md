# B 方案探针：把头部动作交给**系统**工具栏

日期：2026-10-25
版本：2.4.7+14（未 bump —— 这是探针，不是发布）
设备：iPhone Duo 模拟器（iOS 27.1）、iPhone 18 Pro 模拟器（iOS 27.0）

## 要回答的一个问题

Duo 上「工具栏竖排到右侧」是 **`UINavigationBar` 的系统行为**，只会搬它认识的条。
Flutter 自绘的按钮行在系统眼里只是普通视图内容，换 SDK 也不会移动
（`DuoToolbarBridge` 头注里有这条的完整论证）。

所以探针只验证一件事：**把 Flutter 装进 `UINavigationController`、两个动作变成
`UIBarButtonItem` 之后，Duo 会不会真的把它们竖排到右侧，并且看起来不违和。**

## 结论：会，两块屏都竖排

| 屏 | 尺寸 | 结果 |
|---|---|---|
| 内屏（展开，横） | 951×669 | 右侧竖排浮起玻璃胶囊，内含 `+` / `…` |
| 外屏（合上，竖） | 466×678 | 同上，胶囊贴在右侧状态列下方 |
| 非 Duo（iPhone 18 Pro） | 402×874 | **无系统栏**，自绘动作行原样不动 |

截图见 `截图/01-内屏-系统栏竖排.png`、`截图/02-外屏-系统栏竖排.png`。

关键日志（`log show --predicate 'process == "Runner"'`）：

```
[DuoToolbar] attach ok superview=UILayoutContainerView nav={{0,0},{951,669}} root={{0,0},{951,669}}
```

`superview` 是 `UILayoutContainerView`（导航控制器的容器视图），
nav 与 Flutter 视图尺寸一致——说明内容确实在系统容器里，且铺满。

## 踩到的坑：重挂载顺序（两次黑屏）

第一次实现是「先建 nav、再赋给窗口」：

```swift
let nav = UINavigationController(rootViewController: root)
window.rootViewController = nav          // ← 错
```

屏幕全黑。诊断日志给出真因：

```
attach nav=UINavigationController rootView.superview=nil nav.frame={{0,0},{466,678}} root.frame={{inf,inf},{0,0}}
```

`root.view.superview = nil` 且 frame 是 `{inf, inf, 0, 0}`：UIKit 换根时会把**旧根**
的 view 从它的 superview 里摘掉；而此刻旧根的 superview 已经变成 `nav.view`
（因为 `UINavigationController(rootViewController:)` 当场就把它加进去了），
于是 Flutter 视图被移出容器，画面全黑。

正确顺序是**先让空的 nav 成为窗口根，再把内容放进去**：

```swift
let nav = UINavigationController()
window.rootViewController = nav           // 被替换掉的是 root 自己，移除的是它挂在 window 上的 view
nav.setViewControllers([root], animated: false)
```

另加一条兜底：`root.view.superview == nil` 时手动补回去——宁可丑也不能黑屏。

## 代价：系统栏用的是系统前景色，不是品牌紫

胶囊里的 `+` / `…` 是黑色。代码里设了 `navigationBar.tintColor = 品牌紫`，
但 `UINavigationBarAppearance`（本探针用了透明底）会接管按钮外观，
按钮走的是 label 色而不是 tint。要改得配 `buttonAppearance`。

这不是 bug，是一个**要做的设计决定**：
- 保持系统黑 → 更像系统控件，但与我们紫色主色脱节；
- 改成品牌紫 → 一致，但玻璃胶囊里的紫色图标可能显脏。

## 没验证的

1. **点击回调没测过。** `simctl` 没有 tap 子命令（`io` / `ui` 都不支持），
   所以 `onAddTap` 与 `onMenuSelect` 两条链路**一次都没被真实点击触发过**。
   Dart 侧只测到「替代关系」（自绘行让位），测不到「点了会怎样」。
2. **`UIMenu` 没截到。** 同上，打不开下拉菜单，菜单的实际外观、图标、位置都未知。
3. **显示/隐藏切换会改安全区。** 页面被推入新路由时 `visible` 变 false，
   系统栏收起 → Flutter 的 `padding.top` 变化 → 内容会跳一下。探针没处理这个。
4. **半折姿态仍不可达**（与上一轮同因：`simctl` 无 fold，DeviceHub 无窗口）。

## 判据

`test/screens/duo_system_toolbar_test.dart` 两条，守**替代关系**：

| 场景 | 断言 |
|---|---|
| 折叠屏（`supported: true`） | `DuoSystemToolbar` 存在，且 `device-list-add` 不存在 |
| 非折叠（`unsupported`） | `DuoSystemToolbar` 不存在，且 `device-list-add` 存在 |

反向探针已验证：把 `if (!useSystemToolbar)` 改成 `if (true)`，第一条如期变红；
改回后全绿。全套 `flutter test` 133 项通过，`flutter analyze` 无告警。
