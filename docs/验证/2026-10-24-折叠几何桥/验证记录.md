# 折叠屏几何桥验证记录

日期：2026-10-24
版本：2.4.7+14
设备：iPhone Duo（iOS 27.1）、iPhone 17（iOS 27.0），均为模拟器

---

## 一、为什么需要这座桥

Flutter 的 `ViewConfiguration.displayFeatures` 官方文档原文：

> **This list is populated only on Android.**

也就是说，在 iOS 上它**恒为空**。同一时刻在 Duo 外屏实测：

```
view[0] displayFeatures=0        ← 引擎：什么都没有
```

折叠线位置与铰链角度只能从 UIKit 取，而这两组 API 都在 iOS 27.1 才出现：

| API | 头文件 | 能拿到什么 |
|---|---|---|
| `UIHingeInteraction` | `UIKit/UIHingeInteraction.h` | `hinge.status`（unknown/closed/partiallyOpen/fullyOpen）、`hinge.angle`（弧度） |
| `UIView.reservedRegionsOfKind:options:` | `UIKit/UIView.h` | `UIViewReservedRegion` 数组，每项含 `frame`（**在被查询视图的坐标系里**）、`margins`、`isActive`；kind 有 `divisionRegionKind`（折叠分区）与 `occlusionRegionKind`（遮挡） |

Swift 侧的真实名字（`NS_REFINED_FOR_SWIFT` 会把它们加上下划线前缀，编译报错才试出来）：

```swift
__UIViewReservedRegionKind.division()      // 不是 divisionRegionKind()
__UIViewReservedRegionKind.occlusion()     // 不是 occlusionRegionKind()
view.__reservedRegions(of: kind)           // 不是 reservedRegionsOfKind(_:)
view.__reservedRegions(of: kind, options: .includeInactive)
```

## 二、实测数据

探针：`tool/shots/main.dart` 的 `probe` 指令（在 App 内读一次 `flux/duo`，把结果写进沙盒 `tmp/probe.txt`）。

### Duo 外屏（iOS 27.1，466×678）

```
view[0] logical=466.0x678.0 physical=1398.0x2034.0 dpr=3.0
view[0] padding=ViewPadding(left: 0.0, top: 0.0, right: 252.0, bottom: 102.0)
view[0] displayFeatures=0

duo supported=true attached=true
duo view=466.0x678.0 scale=3.0
duo hinge=DuoHinge(closed, 0.0°)
duo verticalFoldX=null horizontalFoldY=null needsSinglePane=false
duo divisions=0 []
duo occlusions=2 [DuoRegion(399.7,29.3,37.0x37.0), DuoRegion(382.0,0.0,84.0x174.0)]
```

三条结论：

1. **铰链真的在回应**：`hinge=closed`，不是 `nil`。这证明 `UIHingeInteraction` 在这个设备上被场景接进了响应链——系统日志里有一条独立旁证：

   ```
   _UISceneTargetingInteraction ... returned sceneRegistrationTarget:
   <_UISceneHingeStateClientComponent: ...>; for reason: did move to view <FlutterView: ...>
   ```

2. **遮挡区与 `MediaQuery.padding` 交叉对上**：`padding.right = 252pt 物理 = 84pt 逻辑`，而最小的那条遮挡区正是 `x=382, width=84`（382 + 84 = 466）。两个完全独立的来源（引擎从安全区推的 padding / UIKit 直接给的保留区）给出同一个数——这是这座桥正确的**最强证据**。

3. **合上时 `divisions=0`**，符合预期：没有折痕就没有分区，所以外屏不会被误判成折叠态。

### iPhone 17（iOS 27.0，402×874）

```
duo supported=false attached=false
duo hinge=null
duo divisions=0  occlusions=0
```

这是**退化路径的实测**：系统低于 27.1 时原生侧返回 `supported=false`，Dart 侧所有 getter 为 null，`AdaptiveShell` 走与改动前完全一致的分支（402 < 800，单栏）。App 正常启动、无崩溃。

> 两台模拟器分属不同 runtime 是巧合（Duo 在 27.1、iPhone 17 在 27.0），正好构成一组正负对照。

## 三、落成的行为

| 条件 | 布局 |
|---|---|
| 拿不到几何（非 iOS / iOS < 27.1 / 桥异常） | 与改动前**逐像素一致**：宽屏左栏 340 + 0.5pt 分隔线 |
| 有竖折分区 | 左栏宽 = 折痕 x，右栏从折痕起，**不画分隔线**（折痕即分隔线）；折痕不在 `[300, 0.55×宽]` 内则退回 340 |
| 铰链 `partiallyOpen` 或存在水平折痕 | 退回单栏（横向双栏会被折痕拦腰切断） |

判据在 `test/models/duo_geometry_test.dart`（13 条）与 `test/screens/duo_fold_layout_test.dart`（8 条）。其中这两条是反向的：

- 「拿不到折叠信息时，双栏与改动前一致（左栏 340 + 分隔线）」——保证桥坏掉也不会改变观感；
- 「非活动分区不改变布局」——UIKit 会把非活动分区一并返回（我们显式请求了 `.includeInactive`），不过滤就会在合盖瞬间错位。

## 四、踩到的两个坑

1. **pbxproj 的 ID 撞车，报错信息完全不指向真因。**
   本工程的 ID 约定是 `AA00010N…NNNN`，我按「下一个可用」用了 `AA000104…0003` / `AA000105…0003`，**这两个 ID 已经被 `Localizable.strings` 占用**。xcodebuild 报的是：

   ```
   error: Unexpected duplicate tasks
   note: Target 'Runner' has copy command from '.../en.lproj/Localizable.strings' ... （同一条重复两遍）
   warning: The file reference for "" is a member of multiple groups ("Runner" and "Runner")
   ```

   ——看起来像本地化文件的问题，实际是新增的 Swift 文件抢走了 `Localizable.strings` 的对象 ID。**定位方式**：`git checkout` 回 pbxproj 后构建成功，说明是自己改坏的；再用「按 `isa = ` 统计 ID 定义是否唯一」的脚本确认。修法是换一对没被占用的 ID（`…0006`）。

   > 教训：改 pbxproj 前先 `grep -o 'AA00010[0-9A-F]*' | sort -u` 看占用情况，改完后统计「对象定义数 == 唯一 ID 数」。

2. **`@available` 必须落在函数上，不能只靠调用处的 `#available`。**
   `regionPayloads(in:kind:)` 的**参数类型**本身就是 iOS 27.1 独有的，函数体里又调 `__reservedRegions`。只在 `geometrySnapshot()` 里写 `guard #available` 不够，编译器仍会在被调用函数的声明与实现处报「only available in iOS 27.1」。给 `regionPayloads` 与 `hingePayload` 各加一行 `@available(iOS 27.1, *)` 才过。

## 五、没做到的

1. **半折姿态没有像素证据。** `simctl` 没有 fold/posture 子命令（`simctl help` 全表核对过），切姿态只能点 DeviceHub 设备窗口的 `Closed / Partially Open / Open` 按钮，而这台机器上 DeviceHub 跑着但**窗口数为 0**（`System Events` 报「不能获得 menu bar 1」，即没有可用 UI）。所以：
   - 「竖折时左栏对齐折痕」——只有坐标断言（951 宽、折痕 475、右栏从 475 起），**没有截图**；
   - 「半折退回单栏」——只有用例，**没有截图**；
   - 真机上 `divisions` 始终是空数组，这条路径从未被真实数据驱动过。
2. **没有在真机（非模拟器）上验过**，也没有测过外接键盘/悬停等其他姿态。
3. 桥本身没有 Swift 单测（Runner target 没有测试宿主）；它的一致性靠上面的 JSON 解析判据 + 一次真机探针。
4. `occlusions` 目前**没有消费者**——布局仍用 `MediaQuery.padding`。它现在的作用是诊断与交叉验证；若将来要做「摄像头周围的构图」再取用。

## 六、复现

```bash
# 1. 起 Duo 模拟器并装包
UDID=$(xcrun simctl list devices available | grep "iPhone Duo" | head -1 | grep -o "[0-9A-F-]\{36\}")
xcrun simctl boot "$UDID"
FLUTTER_XCODE_ONLY_ACTIVE_ARCH=YES FLUTTER_XCODE_ARCHS=arm64 \
  flutter build ios --simulator --debug -t tool/shots/main.dart
xcrun simctl install "$UDID" build/ios/iphonesimulator/Runner.app
xcrun simctl launch "$UDID" ink.ainx.flux

# 2. 触发探针（注意指令行必须带序号，否则被静默跳过）
C=$(xcrun simctl get_app_container "$UDID" ink.ainx.flux data)
printf "1 probe\n" > "$C/tmp/shots_cmd.txt"   # 沙盒里读不到 HOME，文件落在 tmp 而非 Documents
sleep 5 && cat "$C/tmp/probe.txt"

# 3. 截图
xcrun simctl io "$UDID" screenshot "docs/验证/2026-10-24-折叠几何桥/截图/01-外屏-桥生效.png"
```

> 构建必须带 `FLUTTER_XCODE_ONLY_ACTIVE_ARCH=YES FLUTTER_XCODE_ARCHS=arm64`，否则这套工具链会生成两个架构的 lipo 任务而报错。
